# 사용자 업무 흐름 재점검과 개선

한 매장 원장·디자이너·접수 직원의 예약 접수, 현장 수납, 입고, 월말 급여 업무를 직접 조작해 확인했습니다. 실제 고객 대상 설문이나 현장 관찰 결과는 아니며, 구현된 화면과 독립 테스트 매장의 시나리오 검증 결과입니다.

| 확인한 불편 | 반영한 개선 |
| --- | --- |
| 첫 화면의 고객·예약·수납 등록 버튼이 목록만 열어 같은 버튼을 다시 찾아야 함 | 바로 해당 입력창을 열고 고객·예약 정보를 이어받음 |
| 이전 예약·부족 재고·오늘 정산 바로가기의 조회 범위가 안내와 다름 | 목적에 맞는 미처리 예약, 부족 품목, 당일 정산 조건을 적용 |
| 완료된 오전 예약 8개가 오후 다음 고객을 가림 | 미완료 예약을 기본 표시하고 시술 중·방문 고객을 우선 배치. 전체 보기와 숨은 건수 제공 |
| 원장 혼자 운영해도 초기 설정 안내가 계속 남음 | 직원 수 대신 사용 가능한 시술 메뉴 등록 여부로 판단 |
| 메뉴 이동마다 날짜·검색·필터가 초기화되고 새로고침은 첫 화면으로 돌아감 | 로그인 중 조회 조건을 메모리에서 유지하고 현재 화면 URL과 뒤로·앞으로 이동 지원. 로그아웃하면 조회 조건 제거 |
| 브라우저 뒤로가기로 작성 중인 입력을 잃을 수 있음 | 화면 이동 확인 후 초안을 유지하거나 명시적으로 버리도록 처리. 중첩 창 종료 후 스크롤 잠금도 정리 |
| 인터넷은 연결되어 있지만 서버 동기화가 실패한 사실을 알 수 없음 | 마지막 동기화 시각, 최신 자료 확인 실패 안내, 같은 화면에서 재연결 제공 |
| 예약 도중 신규 고객을 등록하려면 기존 입력을 버려야 함 | 예약 안에서 고객 등록 후 원래 시술·시간·메모로 복귀. 동일 연락처의 기존 고객 바로 선택 |
| 직원의 근무·휴게·예약을 대조하며 빈 시간을 직접 찾아야 함 | 선택한 시술 시간과 근무 조건을 반영한 시작 시간 제시. 저장 시 서버가 최종 중복 검증 |
| 고객·시술·품목이 많으면 긴 선택 목록을 훑어야 함 | 이름·연락처·시술·상품·입고 품목 검색, 결과 건수와 필터 초기화 제공 |
| 여러 품목을 받으면 입고 창·일자·메모를 반복 입력해야 함 | 저장 후 다음 품목 기능. 입고일·메모 유지, 품목·수량 초기화, 완료 안내와 다음 입력 초점 제공 |
| 정산에서 특정 단말기 거래와 연결 환불을 대조하기 어려움 | 고객·직원·승인번호 검색, 원거래 승인번호에 연결된 환불 조회, 검색 결과 합계 제공 |
| 직원 등록 후 계정 발급 대상을 다시 찾아야 함 | 직원 저장 후 바로 계정 발급, 직원·이메일 검색, 미발급 필터, 해당 직원 급여 연결 |
| 매달 급여의 고정 조건을 반복 입력하고 이전 지급 명세를 찾기 어려움 | 이전 확정 명세의 기본급·수당·공제 조건 불러오기. 근태·메모는 비우고 당월 매출로 인센티브 재계산. 직원 본인은 최근 확정월부터 조회 |
| 설정 저장 충돌 안내만으로는 무엇을 재확인해야 할지 모름 | 서버의 최신 값과 입력값 비교, 저장된 설정으로 되돌리기 제공 |

## 검증 범위

기존 수납·부분환불·재고·권한·급여 규칙 테스트에 더해 다음 브라우저 회귀 검증을 추가했습니다.

- 고객 등록을 포함한 예약 초안 유지, 중복 고객 선택, 빈 시간 선택과 휴게·중복 제외
- 검색과 필터를 유지한 화면 왕복, 새로고침, 브라우저 뒤로가기 시 미저장 보호
- 서버 동기화 실패 표시와 재시도
- 많은 완료 예약이 있는 날의 다음 고객 표시와 1인 매장 안내
- 연속 입고 성공·실패·재시도 시 입력 보존과 중복 없는 기록
- 모바일 고객·시술 검색 수납, 승인번호로 원결제·환불 대조
- 직원 등록과 계정 발급 연결, 이전 급여 조건 재사용, 직원의 최근 명세 조회
- 설정 충돌 비교와 되돌리기

조회 조건은 브라우저 저장소나 URL에 고객 검색어를 남기지 않고 로그인 중 메모리에만 보관합니다. 새로고침하면 현재 업무 화면은 유지되지만 필터는 기본값으로 돌아옵니다. 입력 중인 업무 내용은 자동 임시 저장하지 않으며 이동·닫기·새로고침 시 보호합니다. 결제 승인, 환불 실행, 세금·보험 자동 계산 등 외부 연동 범위는 기존 안내와 같습니다.
