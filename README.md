# 살롱 데스크 · 미용실 ERP

한 매장에서 원장과 직원이 함께 사용하는 한국어 ERP입니다. 로그인, 오늘의 업무, 예약, 고객 차트, 수납·환불, 매출 정산, 수동 입고·재고, 직원·계정, 급여명세, 매장 설정을 제공합니다. React 화면과 Node.js 서버, SQLite 데이터베이스로 구성하며 데이터는 서버의 `data/salon.sqlite`에 저장합니다.

카드 결제는 **기존 카드 단말기에서 승인하고 ERP에 결과를 기록**합니다. 카드번호·CVC를 입력하거나 보관하지 않습니다.

## Windows에서 실행

1. **[Node.js 24 이상](https://nodejs.org/)**을 설치합니다. npm을 포함한 기본 설치 옵션을 사용하세요.
2. 내려받은 ZIP을 **전체 압축 해제**합니다.
3. 프로젝트 폴더의 **`start.bat`을 더블클릭**합니다.

처음에는 필요한 패키지를 자동 설치하고 화면을 준비한 뒤 기본 브라우저에서 **http://127.0.0.1:4173**을 엽니다. 첫 실행과 의존성이 변경된 업데이트 후에는 인터넷 연결이 필요합니다. 처음 접속하면 매장명과 첫 원장 계정을 등록합니다. 기본 계정이나 샘플 고객은 생성하지 않습니다.

**사용하는 동안 실행 창을 열어 두세요.** 종료할 때 `Ctrl+C`를 누르거나 창을 닫습니다. 다시 더블클릭하면 저장된 계정과 데이터를 그대로 사용합니다. 이미 실행 중이면 기존 ERP 화면을 엽니다. 브라우저가 자동으로 열리지 않으면 실행 창의 접속 주소를 직접 여세요. 설치나 실행에 실패하면 창의 오류 내용을 확인할 수 있습니다.

`start.bat`은 매번 최신 소스를 빌드합니다. 기존 저장소는 실행 창을 종료하고 `git pull`로 업데이트한 뒤 다시 더블클릭하면 됩니다. ZIP으로 업데이트할 때는 **기존 `data` 폴더를 보존**하세요. 이 폴더에 계정·고객·매출 등 저장 데이터가 들어 있습니다. 다른 프로그램이 4173 포트를 사용 중이면 해당 프로그램을 종료한 뒤 다시 실행하세요.

### 개발 명령어로 실행하기

코드를 수정하며 자동으로 화면을 갱신하려면 새 PowerShell 창에서 아래 명령을 차례대로 실행합니다. 코드 안의 명령만 복사하고 `PS D:\capstone>`이나 번호를 함께 입력하지 마세요. 먼저 `start.bat` 실행 창을 종료합니다.

```powershell
cd D:\capstone
node --version
npm ci
npm run dev
```

브라우저에서 **http://127.0.0.1:4173**을 엽니다. 실행 중 PowerShell 창을 열어 두고, 종료할 때 `Ctrl+C`를 누릅니다. 개발 화면과 API 서버를 함께 실행하며 수정 내용이 반영됩니다.

기존에 저장소를 받아 두었다면 변경 사항을 받은 후 의존성을 다시 설치합니다.

```powershell
git pull
npm ci
npm run dev
```

`git pull`에서 로컬 변경 충돌이 나오면 작업 파일을 보존하고 충돌을 해결하세요. `git reset --hard`로 작업을 지우지 마세요. `npm.ps1` 실행 정책 오류가 나오면 같은 명령을 `npm.cmd ci`, `npm.cmd run dev`로 실행할 수 있습니다.

macOS·Linux에서는 `node scripts/start-local.cjs`로 같은 자동 준비·브라우저 열기 기능을 사용할 수 있습니다. 개발 명령은 `npm ci`, `npm run dev`입니다. 로컬 실행은 이 컴퓨터에서만 접근하도록 설정되어 있습니다. 직원의 다른 기기에서 사용할 운영 서버는 아래 배포 절차로 구성합니다.

## 첫 설정 순서

1. 첫 원장 계정을 등록합니다. 비밀번호는 12~128자입니다.
2. **매장 설정**에서 매장명·연락처·주소·영업시간·휴무일을 지정합니다.
3. **직원 관리**에서 직원·역할·근무 요일·시간·휴게시간을 등록합니다. 직원별 로그인 계정을 발급하고 직원은 첫 로그인 때 임시 비밀번호를 변경합니다.
4. **재고 · 입고**에서 시술 재료와 판매 상품을 등록합니다. 시작 재고는 실사 조정으로 입력하고 이후 받은 물품은 수동 입고로 기록합니다.
5. **매장 설정**에서 시술명·가격·소요시간·시술별 재료 사용량을 설정합니다.
6. 고객을 등록하고 예약을 만든 다음 접수 → 시술 → 수납 흐름으로 운영합니다.
7. 매출·환불·재고·급여 기록을 확인하고 첫 백업을 다운로드합니다.

이전 v2 브라우저 저장 데이터를 사용했다면 **직원·품목·고객 등을 새로 입력하기 전에**, 최초 원장 등록 직후 빈 매장에서 설정의 기존 데이터 가져오기를 이용합니다. 가져오기는 원장만 수행할 수 있습니다. 원본을 먼저 별도 보관하세요. 검증에 실패하면 일부만 저장하지 않습니다. 원본 데이터 사본은 서버 백업에 보존하며 미완료된 옛 발주 정보는 새 자동 발주로 전환되지 않습니다.

화면은 작은 화면에서 메뉴를 접고 카드와 스크롤 영역으로 표시합니다. 저장 중 중복 실행을 막고, 입력 중인 창을 닫을 때 변경 사항을 확인합니다. 로그인 만료·네트워크 오류·다른 직원의 저장 충돌을 구분해 안내합니다. 푸터에서 매장과 제품 정보를 확인할 수 있습니다.

예약 중 신규 고객 등록과 빈 시간 선택, 여러 품목 연속 입고, 직원 저장 후 계정 발급, 이전 급여 조건 불러오기를 지원합니다. 메뉴를 오갈 때 조회 조건을 유지하고 브라우저 뒤로가기로도 미저장 입력을 보호합니다. 실제 화면에서 확인한 불편과 개선 내역은 [사용성 재점검 문서](docs/UX_REVIEW_KO.md)에 정리했습니다.

### 수납·환불과 재고

- 기존 카드 단말기에서 실제 승인·취소를 완료한 후 ERP에 기록합니다. ERP 버튼이 단말기에 승인이나 환불을 요청하지 않습니다.
- 시술 수납 시 설정된 재료 사용량, 상품 수납 시 판매 수량을 차감합니다. 재고가 부족하면 거래 전체를 저장하지 않습니다.
- 담당자·결제수단·승인 참조 정보만 정정하면 재고를 다시 차감하지 않습니다. 금액·시술 변경은 해당 내역 환불과 새 수납으로 남깁니다.
- 환불은 남은 수량과 할인 배분을 기준으로 서버에서 계산합니다. 시술에 이미 사용한 재료는 환불로 복구하지 않습니다. 반환받은 상품만 수량을 선택해 재고에 복구합니다.
- 환불은 **환불한 날짜**의 정산에서 차감합니다. 원래 수납 내역은 남습니다.
- 입고는 직원이 추가로 받은 수량을 직접 기록합니다. 현재 수량이 기준 수량 **이하**이면 보충이 필요하다고 표시합니다. 공급업체에 자동 주문하지 않습니다.

### 급여명세

기본급, 항목별 수당·공제, 근로일·시간·연장시간과 계산 근거를 직접 입력합니다. 인센티브는 귀속월의 **할인 후 시술 수납액 − 해당 월 시술 환불액**에 비율을 곱해 원 단위 반올림합니다. 상품 매출은 제외하고, 순 시술 매출이 음수이면 인센티브는 0원입니다.

초안 → 확정 → 지급 기록 순서로 관리합니다. 확정 시 계산 근거와 직원·매장 정보를 보존하며 지급된 명세서는 수정하지 않습니다. 지급 이후 차액은 다음 명세의 추가 수당·공제로 반영합니다. 디자이너와 접수 직원은 본인의 확정·지급 명세서만 조회하고 인쇄하거나 PDF로 저장할 수 있습니다.

세금·4대보험·근태를 자동 산정하거나 은행에 이체하지 않습니다. 실제 계약과 급여 자료에 맞는 공제액·법정 기재 항목은 매장의 급여 담당자가 확인해야 합니다.

## 저장·동시 작업

서버는 로그인 세션과 업무 데이터를 SQLite에 저장합니다. 시술·판매·환불·입고 처리는 한 트랜잭션으로 저장하며 요청 번호가 같은 재시도로 중복 반영되지 않습니다. 다른 직원이 먼저 저장했으면 최신 데이터를 읽고 입력 내용을 다시 확인하도록 안내합니다. 화면은 주기적으로, 창에 다시 돌아왔을 때 최신 정보를 읽습니다. 오프라인 변경을 나중에 자동 전송하지 않습니다.

단일 매장·단일 Node 서버용 구조입니다. 같은 SQLite 파일을 여러 서버 인스턴스가 공유하거나 네트워크 드라이브에 놓지 마세요. 대형 매장·다중 지점·장기 대용량 데이터에는 별도 부하 검증과 데이터베이스 구조 확장이 필요합니다.

## 빌드·검증

```sh
npm run build
npm test
npm run test:e2e
```

브라우저 테스트에 Chromium이 없으면 설치합니다.

```sh
npx playwright install chromium
```

`CHROMIUM_PATH` 환경 변수나 `/usr/bin/chromium`이 있으면 해당 브라우저를 사용합니다. 브라우저 테스트는 별도의 임시 데이터베이스를 사용합니다. 로컬에서 빌드 결과만 확인하려면 `npm run build` 후 `npm start`를 실행하고 **http://127.0.0.1:3001**로 접속합니다. 개발 실행의 4173 포트와 다릅니다.

## 배포·백업·복구

실제 직원용 서버는 **HTTPS 도메인 + Caddy + Node 서버 + 영구 SQLite 볼륨**으로 구성합니다. Docker Compose 구성을 포함합니다. 실제 도메인 연결·서버 배포는 이 저장소를 내려받는 것만으로 실행되지 않습니다.

[배포·백업·장애 복구 안내](docs/DEPLOYMENT.md)에 HTTPS 배포, 초기 설치 토큰, 업데이트, 정기 백업, 전체 복구, 원장 비밀번호 복구 절차를 설명합니다.

로컬 백업은 새 파일명을 지정합니다. 서버가 실행 중이어도 SQLite의 백업 API로 일관된 스냅샷을 만듭니다.

```sh
npm run backup -- backups/salon-2026-10-05.sqlite
```

같은 이름의 기존 백업은 덮어쓰지 않습니다. `.env`는 Git에서 제외됩니다. Node 명령이 `.env`를 자동으로 읽지는 않으므로 직접 운영할 때는 `node --env-file=.env server/index.cjs`를 사용합니다. Docker Compose는 `.env`를 자동으로 읽습니다.
